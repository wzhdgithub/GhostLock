## 概述

GhostLock 是一个安全研究项目，我们高度重视安全问题。如果你发现了安全漏洞，请负责任地披露。

## 报告漏洞

### 重要：不要公开报告安全漏洞

**不要**在公开的 GitHub Issues 中报告安全漏洞。请通过以下方式私下报告：

### 报告方式

**电子邮件：** yjhsbwssg@163.com

### 报告内容

请在报告中包含以下信息：

- **漏洞描述** - 漏洞的具体描述
- **影响范围** - 受影响的版本和平台
- **复现步骤** - 如何复现漏洞
- **潜在影响** - 漏洞可能造成的危害
- **建议修复** - 如果知道，提供修复建议

### 报告模板

```text
主题: [安全漏洞] GhostLock - <漏洞标题>

## 漏洞描述
<描述漏洞>

## 影响范围
- 版本: <受影响的版本>
- 平台: <受影响的平台>

## 复现步骤
1. <步骤1>
2. <步骤2>
3. <步骤3>

## 潜在影响
<漏洞可能造成的危害>

## 建议修复
<修复建议（可选）>
```

## 响应时间

我们承诺在以下时间内响应：

| 阶段 | 时间 |
|------|------|
| 确认收到 | 24 小时内 |
| 初步评估 | 72 小时内 |
| 详细回复 | 1 周内 |
| 修复发布 | 视严重程度而定 |

## 安全更新

安全更新通过以下方式发布：

1. **GitHub Security Advisory** - 安全公告
2. **GitHub Releases** - 版本更新
3. **邮件通知** - 如果你订阅了安全公告

### 漏洞严重程度

我们使用 CVSS v3.1 评估漏洞严重程度：

| 等级 | CVSS 分数 | 响应时间 |
|------|-----------|----------|
| 严重 (Critical) | 9.0 - 10.0 | 48 小时内 |
| 高危 (High) | 7.0 - 8.9 | 1 周内 |
| 中危 (Medium) | 4.0 - 6.9 | 2 周内 |
| 低危 (Low) | 0.1 - 3.9 | 1 个月内 |

## 负责任披露

我们遵循负责任披露原则：

1. **私下报告** - 首先私下报告漏洞
2. **合理时间** - 给予开发者合理的时间修复
3. **协调发布** - 协调漏洞公告的发布时间
4. **公开致谢** - 在公告中致谢安全研究人员

## 安全实践

### 开发者安全实践

- **代码审查** - 所有代码经过安全审查
- **输入验证** - 验证所有用户输入
- **内存安全** - 注意内存安全问题
- **依赖管理** - 定期更新依赖项

### 用户安全实践

- **授权使用** - 仅在你拥有/有权测试的设备上使用
- **定期更新** - 使用最新版本
- **报告问题** - 发现漏洞时及时报告
